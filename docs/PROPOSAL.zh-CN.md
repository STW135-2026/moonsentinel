# MoonSentinel 项目申报书

## 基本信息

- 项目名称：MoonSentinel——多场景数据共享前的授权核验与隐私发布工具
- 项目负责人：苏天纬
- 开源许可证：Apache-2.0
- 代码仓库：<https://github.com/STW135-2026/moonsentinel>

## 项目从什么问题开始

一份数据通过格式和质量检查，不等于它可以直接交给合作方。交付人员还要确认本次用途是否
获准、接收方是否在授权范围内、每条记录是否具有对应同意，以及交付结果中是否仍有能够
识别个人的字段或过小人群。

这不是某一个行业才会遇到的问题。科研机构交换样本、企业把业务数据交给外部服务商、团队
共享用户或设备数据、整理可公开数据集时，都要面对相似的决定：数据是否可以用于这次目的，
接收方是否合适，哪些记录具备授权，哪些字段应当删除或处理，以及小群体是否容易被重新识别。

目前这些条件常散落在临时 SQL、导出脚本和人工表格里；源表新增列时，`select *` 还可能把
新字段一并带出。问题发生后，团队也很难复现当时依据什么放行了哪些行和列。MoonSentinel
把一次发布请求、隐私策略和输出结果绑定起来，让这项检查可以重复执行，并留下可核对的原因。

## 项目做什么

MoonSentinel 是用 MoonBit 编写的数据共享隐私发布门禁。输入可以是 Arrow `RecordBatch`、
JSONL 或 CSV：适配器将文本记录转为 Arrow，再交给同一套发布策略。JSONL 每行一个扁平对象；
CSV 使用首行表头，按 UTF-8 文本列导入；未加引号的空单元格转为 null，`""` 保留为空字符串。调用方
同时提供 `PrivacyPolicy` 和一次 `ReleaseRequest`。请求中写明请求编号、用途和接收方；策略中写明
允许的用途、允许的接收方、每个用途对应的同意值、准标识符、敏感字段及各列的输出方式；
一个用途的同意记录不会自动授权另一个用途。

核心规则不依赖具体行业，按固定顺序处理一次交付：

1. 用途或接收方不在允许范围内时，整批拒绝；
2. 逐行检查同意字段，缺失或不符合策略的记录进入隔离结果；
3. 对候选记录执行 k-匿名和 l-diversity 检查，降低小群体特征带来的重新识别风险；
4. 只输出策略明确列出的字段，直接标识符和敏感字段只能删除或替换；
5. 同时生成可交付数据、隔离数据、拒绝原因和交付回执四个 Arrow 表。

## 一个可运行的例子

仓库中的示例模拟把反欺诈研究数据交给外部合作方。源数据有 6 行，包含用户编号、邮箱、
研究同意、国家、年龄段、案件结果和风险分数。策略要求用途为 `fraud_research`、接收方为
`Partner`，并要求 `country + age_band` 至少形成 2 人的匿名组，组内案件结果至少有 2 个
不同值。

运行后有 4 行进入可交付数据。1 行因没有同意本次研究被隔离，另 1 行因所在匿名组只有
1 人被隔离。用户编号、同意字段和案件结果不进入交付文件，邮箱被替换为 `[EMAIL]`。
交付回执记录请求编号、用途、接收方、处理行数、发布列和匿名阈值。这个结果可以直接通过
Arrow IPC 交给下游系统。

## 项目意义与复用价值

数据质量合格，不等于可以按任意用途交给任意接收方。科研协作或委托处理时，还要核对用途、
接收方、个人同意和可交付字段。若这些检查散落在 SQL、脚本和人工清单里，源数据一变就可能
漏查字段，也难以说明当时为何放行。MoonSentinel 在导出前统一执行这些检查，并记录放行、
隔离和拒绝原因，帮助团队及时发现不符合本次授权的记录，留存可复核的交付结果。

CSV、JSONL 和 Arrow 输入共用同一套发布规则，获准结果也可导回常用文件格式；接入方不用
为每种格式重复编写授权逻辑，只需按用途和接收方配置策略，再把工具接到现有导出流程末端。
因此，这套做法可用于科研数据协作、外部服务商交付或公开数据整理。项目提供的是可复用的
技术检查，不替代业务授权和法律判断。

## 实际使用方式与适用范围

MoonSentinel 放在已有数据导出任务的最后一步。上游继续负责从数据库、业务系统或文件中读取
数据并完成格式、质量检查；本项目只负责按本次请求核验授权与隐私条件，决定哪些行和列可以
交付。相同源数据用于内部分析时可以获准，改为外部服务商、研究协作方或公开用途时则按对应
策略重新判断。

当前版本提供 MoonBit 库和可运行示例。JSONL 与 CSV 输入经适配后使用与 Arrow 输入相同的发布
策略；获准的 Arrow 结果也可序列化回 JSONL 或 CSV，方便接入常见的文本数据交换流程。策略构造、
交付决定和四类 Arrow 输出目前在 Native、JavaScript、Wasm、Wasm-GC 上使用同一套实现。

## 与现有项目的区别

MoonSentinel 不做 CSV 或 JSONL 数据合同、非空检查、范围检查、画像、质量评分和合同差异。
这些属于 MoonVerity 等数据质量工具的范围。MoonSentinel 也不是自由文本敏感词扫描器或
差分隐私查询引擎。它处理的是一次具体的数据交付请求，核心依据是用途、接收方、逐行同意、
匿名组和列级处置。

项目已针对 MoonVerity、MoonRedact、moonbit-fhir、moon-privacy-budget、MoonTrustFlow 等
公开仓库做过功能对照。完整记录见
[差异化核查](https://github.com/STW135-2026/moonsentinel/blob/main/docs/DIFFERENTIATION.zh-CN.md)。

## 已完成成果

- 已实现用途和接收方授权、逐行同意、k-匿名、l-diversity、列白名单和敏感字段处置；
- 已实现 approved、quarantine、findings、manifest 四个 Arrow 输出；
- 已提供 CSV、JSONL 与 Arrow 转换函数；演示将两种文本输入送入同一隐私策略，再导出获准结果；
- 自动化测试覆盖正常交付、授权拒绝、策略失败关闭、匿名性检查、文本往返、Arrow IPC 往返和非法输入；
- 提供 `moon fmt --check`、`moon check --target all --deny-warn` 和 `moon test --target all --deny-warn` 验证命令。

## 当前边界与下一步

JSONL 当前仅支持一行一个扁平对象，嵌套对象和数组不支持；单列混合类型会拒绝，整数与小数
混合时提升为浮点数；绝对值超过 9007199254740991 的 JSON 数值会拒绝，以避免解析精度造成
静默改值。JSONL 导出也使用相同的数值范围限制。CSV 导入列按文本处理，不自动推断数值和布尔类型；未加引号的空单元格转为 null。跨批次匿名统计和更灵活的脱敏策略尚未实现。项目在单个批次内计算匿名组，
敏感字段替换只支持 UTF-8 固定值。隔离结果保留原始行，必须存放在受控区域。项目提供技术检查
和可追溯输出，不替代法务判断，也不宣称 k-匿名和 l-diversity 能消除所有重新识别风险。

下一步评估跨批次处理。CSV 和 JSONL 适配复用现有策略，不另设一套授权规则。
