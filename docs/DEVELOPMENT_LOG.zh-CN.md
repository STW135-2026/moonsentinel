# MoonSentinel 开发与差异化记录

本文记录可由代码、测试和 Git 历史核验的方向调整，避免项目定位只停留在申报文案。

## 2026-09-29 根据初审意见扩大项目适用范围

### 触发原因

初审指出项目场景偏窄，且当前只接收 Arrow，通用价值和复用空间说明不足。

### 本次调整

- 项目名称改为“多场景数据共享前的授权核验与隐私发布工具”；
- 申报书补充科研样本交换、外部服务商数据交付、团队数据共享和公开数据集整理等使用情境；
- 说明 Arrow 是当前实现的输入边界，而不是已经支持多格式的产品承诺；
- 将 JSONL/CSV 适配列为后续接入工作，不描述成已完成成果。

本次调整是对项目定位和申报材料的修订，没有改变现有代码能力。当前输入仍为 Arrow `RecordBatch`，
因此文件型和非 Arrow 工作流的接入成本仍需后续解决。

## 2026-09-29 增加 JSONL 接入

根据评审对输入格式单一的反馈，新增 JSONL 与 Arrow 的适配函数。JSONL 行会被解析为扁平
Arrow 列；获准结果可再输出为 JSONL，发布仍走原有同一套策略。

- 缺失字段和显式 null 转为 Arrow null；
- 支持字符串、布尔、整数和小数，整数/小数同列时提升为浮点；
- 对嵌套值、混合类型和超出精确数值范围的输入显式报错；
- 增加端到端发布、获准数据导出、缺失值和错误输入测试；
- Native、JavaScript、Wasm、Wasm-GC 共 12 项测试全部通过。

嵌套 JSONL 和跨批次匿名统计仍未实现。

## 2026-09-29 增加 CSV 接入

CSV 现在可以和 JSONL 一样进入同一套隐私发布策略。CSV 适配要求首行为唯一、非空表头，
支持逗号、双引号转义、LF/CRLF 和引号内换行。由于 CSV 本身不声明列类型，导入列统一按
UTF-8 字符串处理；未加引号的空单元格转为 null，`""` 保留为空字符串。获准的 Arrow 批次可导出为 CSV。

- 演示增加 CSV 输入、发布和获准数据导出往返；
- 新增 2 项 CSV 测试，覆盖转义、UTF-8、空值往返、发布过滤和非法输入；
- CSV 合入时测试总数为 14 项；该版本经复核后，在 Native、JavaScript、Wasm、Wasm-GC 四个目标全部通过。

## 2026-09-29 修正用途同意绑定与 JSONL 数值往返

- 同意值改为按每个允许用途分别配置；策略缺少用途配置或出现未授权用途配置时拒绝创建；
- 增加多用途回归测试，确认某用途的同意值不会让其他用途的记录通过；
- JSONL 导出现在与导入采用相同的精确数值范围，超界 Int64/Float64 显式报错，并增加边界往返测试；
- README 演示输出补上已实际运行的 CSV 交接行。
- 目前共 16 项自动化测试，四个目标均已全部通过。

## 2026-09-26 合作数据交付场景收敛

### 触发原因

上一版申报书压缩过多，只列出用途、接收方、同意和匿名算法，没有说明谁会使用工具、现有
交付方式为什么容易出错，以及四类 Arrow 输出如何进入真实工作流。

### 本次调整

- 项目名称改为“合作数据交付前的授权核验与脱敏工具”；
- README 和申报书从外部合作方数据交付场景开始说明；
- 明确 approved 是唯一可交付输出，quarantine 留在内部受控区域；
- 用 6 行反欺诈研究样本说明 4 行放行、2 行隔离和字段最小化结果；
- 保留现有代码边界，不增加数据质量、画像、合同 diff 或通用查询功能。

本次调整没有虚构新功能。用途和接收方授权、逐行同意、k-匿名、l-diversity、列处置、
findings 和 manifest 均有现有实现与测试。

## 2026-09-20 隐私发布方向重构

### 触发原因

复核 `Wchwch777/MoonVerity` 后确认，旧版 MoonSentinel 的 Required、非空、范围、枚举、
唯一性、质量报告等能力与其数据质量门禁存在明显重叠。

### 已移除的重叠面

- 通用 `Contract`、`Rule`、`Severity` 和 `ValidationReport` 公共模型；
- Required、NotNull、Range、AllowList、Unique、跨字段比较等质量规则；
- “质量合格或不合格”作为核心项目价值的表述；
- 把通用质量诊断、数据画像或合同差异列入路线图的表述。

### 已落地的新能力

- `ReleaseRequest` 绑定请求编号、用途和接收方；
- `PrivacyPolicy` 定义用途与接收方允许列表；
- `ConsentRequirement` 对每行核验当前用途的同意；
- 在同意候选集内执行多列 k-匿名，避免未授权记录虚增群体；
- 在通过 k-匿名的固定候选集内执行敏感属性 l-diversity；
- `DataClass` 与 `Treatment` 强制敏感列删除或替换；
- 未配置字段默认不进入获准数据，实现失败关闭的数据最小化；
- 同时返回 approved、quarantine、findings 和 manifest 四类 Arrow 批次。

- 演示输出验证 6 行输入、4 行放行、2 行隔离、字段最小化、邮件替换和 IPC 交接。

## 后续差异化复核清单

每次扩展前先回答以下问题：

1. 新能力是否属于通用数据质量、数据画像或合同差异；
2. 是否直接支撑用途、接收方、同意、再识别风险或审计证据；
3. 是否能通过新的公开 API 和自动化测试证明，而不是只修改文案；
4. README、Markdown 申报书、Word 申报书、演示与代码是否保持同一口径；
5. GitHub 是否出现新的同类 MoonBit 项目，需要更新对比说明。

计划中的 t-closeness、策略版本签名和可验证发布清单也必须通过这份清单后再实现。
